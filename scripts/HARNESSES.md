# The checks in `scripts/`, and which should pass

Every browser check drives headless Chrome for Testing through `scripts/lib/browser.mjs`, through
the machine's queue (see `AGENTS.md`), one at a time.

**The gate has its own server, and its database is made from nothing.** `scripts/gate.mjs` starts
a server on a free port (`scripts/lib/gate_db.mjs`: the migrations and nothing else, none of a
developer's `.dev.vars` or database), puts the made-up trip on it whole (`seed/demo-trip.json`,
every row through the routes a person's write goes through: four made-up people, places, plans,
purchases, packing), and gives each check that drives it two settings: `WGP_BASE`, the server's
address, and `WGP_GATE_CARD`, a file that names the trip and its people. A check asks
`scripts/lib/gate_trip.mjs` for the trip's id, its addresses, its people and a signed-in session
of any of them; no check writes a trip's id, an account's id or a cookie into its own text. The
server is stopped and its folder removed when the gate ends, so a run says the same thing on any
machine and no still taken on it shows anyone's trip. No dev server has to be up, and none is used.

```sh
# the whole gate, in turn, each check with a ceiling (command sandbox off)
node scripts/gate.mjs --who <session>
# some of it: every check whose name holds one of the words
node scripts/gate.mjs --who <session> --only "toast,first_focus"
# a server kept up, to run checks against by hand: it prints the two settings
node scripts/gate.mjs --serve
WGP_GATE_CARD=<the card it printed> node scripts/gate.mjs --who <session> --only <words>
```

**A check removes only rows it made, each by the id it recorded when it made it.** Never "the
first row", "the last" or "the newest": on a trip that has rows of its own, the first row of a
list is not the one a check just added (the made-up trip's purchases are dated after today),
and a cleanup that takes it for its own deletes a row of the trip. That happened once
(`split_ui_harness`, 14 Nov 2026). The gate now holds every check to it: it reads the key of
every row of the made-up trip before and after each check that drives it
(`scripts/lib/gate_db.mjs`, `tripRows`), and a check that leaves a row of the trip gone, or a row
of its own behind, has failed whatever its tally says; its line names the table and the rows.

**Nothing on the gate reads a developer's `.dev.vars`.** The gate's server has its own settings,
and its people sign in with the passkey they signed up with (`scripts/lib/gate_trip.mjs`). A
helper once read the developer's secret when it was loaded, so every browser check passed only in
a tree that happened to hold that file (15 Nov 2026: five of six checks stopped in a tree without
one). `scripts/lib/dev_secret.mjs` is asked only where an old-style cookie is made, never at
load, and the gate marks its checks (`WGP_GATE`) so that asking is refused there, on every
machine alike.

A check with a server of its own (most of the newer ones: "on a server of its own" below) starts
it itself and needs neither setting. A check off the gate that still drives a developer's server
takes its address in `WGP_BASE`, the address that server calls its own (`PUBLIC_ORIGIN`): the
server refuses a change that comes from any other origin, so `http://localhost:<port>` and
`http://127.0.0.1:<port>` are not interchangeable.

Nothing waits for ever. The launcher ends a harness whose DevTools call goes unanswered for
`WGP_CALL_CEILING_S` (120 s) or that runs longer than `WGP_RUN_CEILING_S` (900 s), with exit 124
and a line naming the call. `gate.mjs` stops whatever is still there after `WGP_GATE_CEILING_S`
(1000 s). A laptop that slept mid-check is said to have slept, and that check runs once more.

"Green" below means green on the gate's server: the made-up trip as it is made, and whatever the
checks before it left (each check puts back what it changed).

## What each check reads (gate.mjs --affected)

`node scripts/gate.mjs --affected <base>` runs only the checks a branch's files can affect (scripts/lib/affected.mjs): a
check runs when a file it reads changed since `<base>` (committed or not). What a check reads is its own script with
everything it imports, and what its row below declares: files and globs, a declared module or page counting with
everything it loads (a script's imports, a page's scripts, inline modules and stylesheets, a stylesheet's @imports).
`@app` is the app around every browser check: `public/index.html` as loaded (the shell), the worker, the manifest,
the headers, `public/vendor`, and the server (`src`, `migrations`, `wrangler.jsonc`); a section's own module
(`split.js`, `packing.js`) is not in it, so a change there runs only the checks that declare it. `(its imports)`: the
script's own imports and nothing more. ALWAYS RUN, whatever changed: journey, check:parity, sw_version_check, sw_topup_test,
a11y_check and first_screens_check, and every check with no row here (theme_contrast, test-browser-launcher). A change
to the gate, to affected.mjs or to the packages runs every check. Unsure what a check reads: declare `public/**`.
Held by `scripts/affected_test.mjs`.

## Where a check writes

Stills go to the folder named in `WGP_SHOTS`, or to a temp folder when it is unset. Some older
checks still write stills into `docs/`: read `git status` after a run and put them back with
`git checkout -- docs`. A check's own temp folders (`$TMPDIR/wgp-*`) are the runner's to remove.
